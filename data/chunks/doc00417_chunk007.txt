/ bin / sh pattern = " $ 1 " shift awk ' / ' " $ pattern " ' / { print filename " : " $ 0 } ' " $ @ " the $ pattern in the awk command is not protected by single quotes so that the shell does expand the variable but it needs to be put in double quotes to properly handle patterns containing spaces. a pattern by itself in the usual way checks to see if the whole line ( $ 0 ) matches. filename contains the current filename. awk has no explicit concatenation operator ; two adjacent strings concatenate them. $ 0 expands to the original unchanged input line. there are alternate ways of writing this. this shell script accesses the environment directly from within awk : #! / bin / sh export pattern = " $ 1 " shift awk ' $ 0 ~ environ [ " pattern " ] { print filename " : " $ 0 } ' " $ @ " this is a shell script that uses environ, an array introduced in a newer version of the one true awk after the book was published. the subscript of environ is the name of an environment variable ; its result is the variable ' s value. this is like the getenv function in various standard libraries and posix. the shell script makes an environment variable pattern containing the first argument, then drops that argument and has awk look for the pattern in each file. ~ checks to see if its left operand matches its right operand ;! ~ is its inverse. note that a regular expression is just a string and can be stored in variables.
